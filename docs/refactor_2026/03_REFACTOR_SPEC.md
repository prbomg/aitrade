## 3. Спецификация Модуля 1: «Разгон» (`$1,000 → $10,000`)

### 3.1. Торговые стратегии Разгона (`aitrade/strategies/booster_breakout.py`)
Отключить `OISqueezeScanner` от автоторговли до отдельной валидации (оставить только как информационную панель с исправленными порогами: ликвидации `>= $50,000` за 5m, только закрытые свечи `k_list[1:]`).

Внедрить два проверенных ядра для Разгона (таймфреймы `15m` / `1h` / `4h`):
1. **Ядро B1 — Volatility Squeeze + Supertrend Breakout (`15m/1h`):**
   - Режим: `TREND_UP` или `TREND_DOWN`.
   - Предварительное сжатие: полосы Боллинджера `(20, 2.0)` внутри канала Кельтнера `(20, 1.5–2.0 ATR)` хотя бы на 2 из последних 5 баров.
   - Пробой закрытой свечой за границу канала в направлении `Supertrend(1h)` и `EMA20/EMA50(1h)`.
   - Подтверждение объёма: `RVOL >= 1.35` (выше 120–135% от 20-барного среднего).
   - Фильтр фандинга: запрет лонга при `fundingRate > +0.03%` за 8ч, запрет шорта при `fundingRate < -0.03%` за 8ч.
2. **Ядро B2 — Исправленный `S1_TREND_RETEST` (`15m`):**
   - Бокс пробоя: 12 закрытых баров в подтверждённом `TREND_UP` / `TREND_DOWN`.
   - **Исправление цены входа:** для `Buy` лимитная цена ретеста `entry_px = min(box_high + 0.05 * atr15, best_bid - tick_size)` (гарантия `PostOnly` ниже рынка, чтобы не исполняться как Taker); для `Sell` — `max(box_low - 0.05 * atr15, best_ask + tick_size)`. TTL лимитки — 3 бара (45 мин).

### 3.2. Стопы, тейки и сопровождение Разгона
- **Минимальный стоп-лосс:** `SL_dist = max(1.2% цены, 1.5 * ATR15)` (на мейджорах от `1.0%`, на альтах от `1.5%`).
- **Цели (асимметрия):** `TP1` = 30% объёма на `+1.8R` (или `+2.0R`), основной `TP2` на `+3.0R…+3.5R` (или выход по трейлингу).
- **Перенос в безубыток и трейлинг (`smart_position_manager.py`):**
  - Безубыток (`avg * (1 ± 0.0015)`) только после прохода `+1.2R`.
  - Трейлинг-стоп: **волатильностный `max(1.5%, 1.8 * ATR15_pct)`** (вместо фиксированных `0.85%`), активируется только после `+1.8R`.
- **Максимум времени в сделке (vertical barrier):** 24 бара (6 часов на 15m) или 48 баров на 1h.

### 3.3. Мани-менеджмент и Сейф-храповик (`aitrade/booster/deposit_booster.py`)
- **Убрать искусственный потолок `$1,000` на риск-капитал** внутри выделенного субаккаунта Разгона — риск считается от *текущего* `current_equity` субаккаунта.
- **Риск на сделку (дробный Келли):** `4.0%` от текущего баланса субаккаунта (настраиваемо `3.5%–4.5%`).
  - Авто-демпфер просадки: если `current_equity` упал на `>= 20%` от `high_water_mark`, риск автоматически режется вдвое (`2.0%`) до восстановления HWM.
- **Опциональный пирамидинг строго в прибыль (флаг `allow_pyramid`):** максимум 1 добавка размером `0.5x` от базовой позиции после прохода `+1.5R`, только после переноса общего стопа в безубыток и пересчёта совокупного риска (совокупный риск к общему стопу не выше `0%` от исходного баланса).
- **Сейф-храповик (`Ratchet Vault`):**
  - Ввести поля `vault_usd`, `next_ratchet_equity` (по умолчанию `start_equity * 1.5` или `* 2.0`), `ratchet_skim_pct` (`0.35` при шаге `+50%` или `0.50` при шаге `2x`).
  - При достижении `current_equity >= next_ratchet_equity` фиксировать `skim = (current_equity - prev_base) * ratchet_skim_pct` в `vault_usd` (с рекомендацией/API-переводом на субаккаунт `autotrade`), обновлять `prev_base` и `high_water_mark`.
- **Лимиты безопасности Разгона:**
  - Максимум `2` открытых позиции одновременно, максимум `1` позиция на сектор, совокупный открытый риск `<= 7%`.
  - Максимальное плечо: `5x` (при `4%` риска и стопе `1.2%–1.5%` эффективное плечо `2.6x–3.3x`).
  - Дневной Kill-Switch: `-8%` (2 полных стопа за сутки -> пауза до 00:00 UTC).
  - Стоп цикла: `-35%` от `high_water_mark` -> заморозка модуля до ручного аудита.

## 4. Спецификация Модуля 2: «Автотрейдинг» (высокий винрейт + надёжность)

### 4.1. Пул инструментов и торговые часы (`config/settings.json`)
- Разделить `universe` на два списка:
  - `autotrade_pairs` (10–12 самых ликвидных пар): `BTCUSDT`, `ETHUSDT`, `SOLUSDT`, `XRPUSDT`, `BNBUSDT`, `SUIUSDT`, `LINKUSDT`, `AVAXUSDT`, `NEARUSDT`, `AAVEUSDT`, `DOGEUSDT`, `ADAUSDT`.
  - `booster_pairs`: расширенный список волатильных ликвидных пар с 24ч оборотом `>= $30M` и спредом `< 0.08%` (исключить неликвидные мемкоины с высоким проскальзыванием).
- Для направленных сделок Автотрейдинга добавить фильтр ликвидных сессий: `07:00–20:00 UTC` (отключать новые направленные входы в тонкие ночные часы).

### 4.2. Три слабокоррелированных рукава Автотрейдинга
1. **Рукав A (40% капитала) — Исправленный `S3_VWAP_RANGE` (`15m/1h`):**
   - Активируется **строго** в режиме `RANGE` (`ADX(1h) < 20`, `ATR_pct < 40%`, `Hurst < 0.45`).
   - Вход: касание `VWAP ±2σ` (или `|z-score| >= 1.5`, `RSI(14) < 30` / `> 70`) + подтверждение ослабления встречного потока (`OBI` / `CVD` не против входа). Убрать запаздывающий фильтр `close > prev_bar.high`, заменив его на закрытие бычьей/медвежьей разворотной свечи с фитилём отбоя.
   - **Исполнение:** строго `Limit PostOnly` (комиссия `0.02%` Maker).
   - **Геометрия сделки:** `SL >= max(0.80%, 1.2 * ATR15)`, цель `TP = VWAP`, **минимальный `R:R >= 1.15`** (сделки с `R:R < 1.15` отбраковываются).
   - **Вертикальный барьер:** закрытие по рынку (`ReduceOnly`) через 12–16 баров (3–4 часа), если цель не достигнута. Без раннего безубытка.

2. **Рукав B (35% капитала) — Кросс-секционный «Моментум + Фандинг» (`aitrade/strategies/momentum_funding.py`, `1h/4h`):**
   - Раз в 4 часа (на закрытии 4h свечи) ранжировать `autotrade_pairs` по скорректированному на волатильность моментуму (`ret_24h / natr_1h`) и ставке финансирования (`fundingRate`).
   - Лонг топ-1–2 сильных монет с дешёвым/отрицательным фандингом; Шорт топ-1–2 слабых монет с высоким положительным фандингом.
   - Автоматическая ребалансировка каждые 4–8 часов или выход по `SL = 2.0 * ATR(1h)`.

3. **Рукав C (25% капитала) — Дельта-нейтральный Funding Carry (`aitrade/strategies/funding_carry.py`):**
   - Мониторинг пар со стабильно высокой положительной ставкой финансирования (`fundingRate >= 0.025%` за 8ч, устойчиво не менее 9 интервалов / 3 суток).
   - Открытие равного номинала: Long Spot + Short Linear Perp (плечо `1x–2x`, резерв маржи `>= 30%`, контроль базиса и окупаемости комиссий).
   - Выход при падении средней ставки ниже `0.005%/8h` на протяжении 3 интервалов подряд или при переходе в отрицательный фандинг.

### 4.3. Мани-менеджмент и Kill-Switch Автотрейдинга
- Риск на направленную сделку: `0.75%–1.0%` от капитала субаккаунта `autotrade`.
- Максимальное плечо: `3x`, максимум `3` открытые направленные позиции, не более `1` на сектор.
- Лимит дневных сделок: не более `6–8` в день.
- Трёхуровневый Kill-Switch:
  1. Дневной убыток (реализованный + плавающий) `<= -2.5%` -> отмена лимиток, пауза новых входов до 00:00 UTC.
  2. Просадка от пика `-8%` -> автоматическое снижение риска вдвое (`0.4%–0.5%`).
  3. Просадка от пика `-15%` -> полная остановка модуля + алерт.
  4. Dead-man's switch: потеря WS/API связи свыше `30` секунд -> отмена всех неисполненных входных лимитных ордеров (`cancel-all` не-`reduceOnly`) и алерт оператору.

## 5. Пересборка ML-слоя, Калибратора и Бэктестера

### 5.1. Реальный Meta-Labeling (`aitrade/ml/meta_labeler.py`)
- Полностью удалить `0.68 * signal.base_winrate_est` и ручные `+0.145` бонусы.
- Использовать `LightGBM` (или `LogisticRegression` / `HistGradientBoostingClassifier` из `scikit-learn`) с вероятностной калибровкой (`CalibratedClassifierCV`).
- Обучение на оффлайн/периодически обновляемом датасете (минимум `500–1,000+` исторических сигналов по каждой стратегии, собранных из расширенного бэктестера + живого `Ledger`).
- **Разметка:** строго Triple Barrier Method (`1` — достигнут TP сверх комиссий, `0` — SL или истечение временного барьера).
- **Валидация модели:** Purged K-Fold / CPCV с удалением перекрывающихся интервалов сделок и буфером embargo `1%`.
- **Холодный старт:** пока реальных исторических сэмплов `< 100`, модель возвращает честный статус `WARMING_UP` (без фейкового винрейта 75%) и пропускает сделки базовой стратегии, только если она прошла WFA-бэктест.
- **Cost-Aware Filter:** рассчитывать ожидаемую доходность `E[R]` строго по откалиброванной `P_cal(win)` и реальному `R:R` сигнала за вычетом полных издержек (`maker/taker + spread + slippage`). Порог отсечения: `P_cal >= 0.50–0.55` (Разгон) и `P_cal >= 0.60–0.65` (Автотрейдинг).

### 5.2. Исправление `AdaptiveMLCalibrator` (`aitrade/booster/ml_calibrator.py`)
- Запретить вечный `QUARANTINE` по 3 стопам подряд.
- Новые правила статусов (активируются только при `trades >= 20` по стратегии):
  - `COOLING` (`weight = 0.5x`): при `PF < 0.90` или `streak <= -5`.
  - `QUARANTINE` (`weight = 0.0x`, блок реальных входов): только при `trades >= 25` и `PF < 0.75`.
  - **Автовыход из `QUARANTINE`:** задать `quarantine_until_ts = now + 48h` (либо вести счётчик виртуальных «теневых» сделок и возвращать стратегию в `COOLING 0.5x`, когда последние 10 теневых сделок имеют `PF >= 1.1`).
- Убрать вызов `calibrate_from_closed_pnl()` из `get_full_state()`. Вызывать калибровку **только при появлении новой закрытой сделки** (сравнение хэша/количества закрытий) или по кнопке в UI.

### 5.3. Честный многомесячный Walk-Forward бэктестер (`aitrade/backtest/walk_forward.py`)
- Реализовать загрузку истории с пагинацией по параметру `end` (`/v5/market/kline`) и локальным кэшированием в `data/candles_cache/` — минимум **180–365 дней** по 15m/1h/4h свечам.
- Реализовать **Rolling Walk-Forward** (минимум 6–8 циклов, 75% IS / 25% OOS) с расчётом:
  - `WFE` (Walk-Forward Efficiency = Annualized OOS / Annualized IS),
  - честного `Sharpe Ratio` (по дневной кривой эквити mark-to-market), `Deflated Sharpe Ratio (DSR)` с учётом числа испытанных конфигураций `N_trials`,
  - `Max Drawdown`, `Profit Factor`, `Win Rate`, `Avg R`,
  - **стресс-теста 2x издержек** (удвоенные комиссии и проскальзывание) и **Монте-Карло перестановки порядка сделок** (5,000 итераций, вывод P95 Max DD).
- Подключить к бэктестеру **все** боевые стратегии: `B1 (Squeeze Breakout)`, `B2 (S1 Retest)`, `S3_VWAP_RANGE`, `Momentum+Funding`.
